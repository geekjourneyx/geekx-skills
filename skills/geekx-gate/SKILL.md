# GeekX 总闸门

## 使命

在行动变成成本前，判断是否允许继续。

这个技能不是泛用评审、不是架构顾问、不是计划生成器。它只做四件事：

1. 判断现在到底在决定什么。
2. 判断这个决定会锁定什么承诺。
3. 排除当前不该做的范围。
4. 给出一个可执行、可停止的下一步。

## 问题分类

先分类，再判断。不要跳过分类。

| 类型 | 进入哪个闸门 |
| --- | --- |
| 需求、功能、范围、路线图、智能体输出是否该做 | 范围闸门 |
| 框架、重写、插件系统、工作流引擎、多智能体架构、模块边界是否该固化 | 承诺闸门 |
| 既有范围膨胀，又有难回滚技术选择 | 先范围闸门，再承诺闸门 |
| 普通代码评审、文案润色、写作、调试、实现任务 | 不使用本技能，转向更具体的任务 |

## 范围闸门

问：**这件事现在该不该存在？**

按顺序检查：

1. 现在解决什么问题？
2. 不做会坏掉什么？
3. 有没有重复痛点或真实失败？
4. 哪些内容只是未来假设、镀金、平台化、角色化或顺手添加？
5. 最小必要动作是什么？

裁决只能选一个：

```text
保留 / 砍掉 / 延期 / 先验证 / 缩小范围
```

范围闸门未通过时，禁止进入承诺闸门。

## 承诺闸门

只在范围已经成立，且出现难回滚技术选择时执行。

问：**这个做法现在该不该固化？**

按顺序检查：

1. 当前系统或工作流是什么？
2. 真实失败或压力是什么？
3. 谁受到影响？
4. 不改变会坏掉什么？
5. 回滚成本是什么？
6. 哪个最小实验能验证压力？

状态只能选一个：

```text
STOP / HOLD / PROBE
```

- `STOP`：这不是技术承诺问题，或当前证据直接否定了承诺。
- `HOLD`：证据不足，只收集证据。
- `PROBE`：只跑一个可回滚实验，不固化架构。

`PROBE` 不能出现在范围未成立的场景。

## 输出格式

默认输出：

```markdown
## 问题类型
范围问题 / 承诺问题 / 混合问题 / 不适用

## 范围闸门
保留 / 砍掉 / 延期 / 先验证 / 缩小范围 / 跳过

## 承诺闸门
STOP / HOLD / PROBE / 跳过

## 原因
[1 到 3 句。先说坏消息。]

## 现在不要做
- [本轮必须排除的范围、技术承诺、流程或抽象。]

## 最小下一步
1. [只给一个动作。]

## 停止条件
[什么时候停止、撤销或拒绝继续。]
```

## 失败分支

| 情况 | 处理 |
| --- | --- |
| 证据太少 | 范围闸门输出“先验证”，最多问 3 个问题，问题必须指向用户、失败、不做后果。 |
| 用户要求完整方案 | 🔴 CHECKPOINT：拒绝完整方案，只给闸门裁决和一个下一步。 |
| 用户要求架构推荐 | 🔴 CHECKPOINT：不推荐架构；范围成立时才进入承诺闸门。 |
| 没有难回滚技术选择 | 承诺闸门必须为“跳过”。 |
| 输出开始变长 | 立刻压回输出格式。 |

## 永远不要

- 不要做泛用评审。
- 不要写完整计划。
- 不要推荐架构。
- 不要比较框架优劣。
- 不要用未来可能性证明当前范围。
- 不要用最佳实践证明技术承诺。
- 不要给超过一个下一步动作。
- 不要把 `PROBE` 写成正式落地。

## 点名入口

如果用户明确调用 `geekx-scope-gate`，执行本技能的范围闸门。

如果用户明确调用 `geekx-commitment-gate`，先确认范围是否成立；成立且存在难撤回技术选择时，执行本技能的承诺闸门。
